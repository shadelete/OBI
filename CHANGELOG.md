# Зміни (Changelog)

Усі зміни до застосунку OBI. Формат засновано на [Keep a Changelog](https://keepachangelog.com/uk-UK/1.1.0/).

## [0.2.0-beta.2] — 2026-09-04

### Виправлено
- **Оновлення тепер працює на 100%**: повністю переписано механізм застосування оновлень:
  - Закриття застосунку та заміна виконуваного файлу більше не залежать одне від одного: нова версія встановлюється **автономним прихованим інсталером**, який запускається через detached `wscript` → `VBS` → `PowerShell` і переживає закриття OBI (Electron вбиває власних дітей — це було причиною зависань).
  - Інсталер чекає повного виходу застосунку (звільнення exe), замінює файли з повторними спробами та сам перезапускає OBI — нічого вручну.
  - Жодного консольного вікна (wscript — GUI-підсистема, PowerShell — `-WindowStyle Hidden`).
  - Кириличні шляхи передаються аргументами (UTF-16), без вбудовування в скрипти (раніше bat-файли в cp866 перетворювали шляхи на моябейк).
  - Тимчасова тека тепер унікальна на кожен запуск (`obi-update-<ts>`) — залишки не блокують (EBUSY).
  - Діагностика: інсталер пише `upd.log`, тест-режим `OBI_TEST_UPDATE` дозволяє перевірити весь флоу без UI.
- **Супутній висновок**: Windows **не** дозволяє перейменувати/перезаписати запущений portable-exe (EBUSY) — тому заміна виконується лише після виходу застосунку.

## [0.2.0-beta.1] — 2026-09-03

### Виправлено
- **Профілі з однаковою назвою, але різним матеріалом** більше не зливаються в одну позицію: ключ агрегації в `OBI.js` змінено з `name` на `name|material` (аналогічно матеріалам, де ключ `name|thickness`). Раніше при наявності двох профілів з ідентичною назвою та різним `MaterialName` другий мовчки зливався в перший, втрата відбувалася на етапі генерації JSON.
- **Округлення розмірів**: замість `Math.round` (цілі числа) в `OBI.js` введено допоміжну функцію `r4()` — округлення до 4 знаків після коми. Прибирає артефакти floating point (напр. `376.99999999999096` → `377`) і зберігає справжні десяткові (напр. `100.5`).
- **Оновлення (updater)**: додано обробку HTTP-редіректів (302) при завантаженні оновлень з GitHub. Раніше завантаження падало з помилкою «HTTP 302», оскільки GitHub asset URL перенаправляє на CDN.

  - Перемикання **теми**: світла / темна (через CSS-змінні в `styles.css`).

- IPC-методи `get-config`, `save-config`, `get-app-info` (у `main.js`/`preload.js`).
